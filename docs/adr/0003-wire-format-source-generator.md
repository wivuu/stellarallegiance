# The wire format is declared once and its codecs are source-generated

The binary game protocol was hand-written four times over: a server writer (`server/Net/Protocol.cs`),
a client reader (`client/scripts/net/FrameApplier.cs` + `DefsApplier.cs`, re-typing every message id
and flag bit as a bare number), a client writer (`GameNetClient.cs`, packing offsets by hand) and a
server reader (`ClientHub.ReceiveLoop`, parsing inbound frames at fixed offsets), plus hand decoders in
the test suites and a fifth copy in `tools/simbot`. Twelve protocol bumps in ten weeks each touched two
to four of those, and the only thing keeping the layouts aligned was "mirror exactly" comments. The
next roadmap items (2–6 teams, turrets, ripcord) would each repeat that.

We decided that a frame or record is a partial C# type in `shared/Net/` whose public fields, in
declaration order, ARE its byte layout, and that a Roslyn incremental source generator
(`tools/wire-gen`, an analyzer reference on `Shared.csproj`) emits `Measure`/`Write`/`Read`/`TryParse`
for every type marked `[WireMessage(id)]` or `[WireRecord]`. Field types pick the encoding; a small
attribute vocabulary (`[Wire(WireEnc.Pos|Half|Quat|Angle|U8|U16|U32|StrU8|Str7Bit)]`, `[WireCount]`,
`[WireOptional]`, `[WireIgnore]`) covers the quantized, narrowed, optional-tail and count-prefixed
cases the existing layouts use. The content defs in `shared/Defs.cs` are the wire records themselves
(made partial), so a new authored field is one line in one file. The server keeps a thin fill layer
(`server/Net/Frames.cs`) mapping sim types into the records; the client reads the same records.

## Why a generator rather than the alternatives

- **Hand-written symmetric `Serialize(ref Archive)`** removes the reader/writer mirror but still
  lists every field twice (declaration + codec line) and cannot give compile-time record sizes; the
  hub strides its per-tick scratch buffers by those sizes.
- **MemoryPack / MessagePack** would shrink the def blocks but change every byte layout, cannot express
  per-field quantization (i16 sector-local positions, smallest-three quaternions, f16 rates) without
  wrapper types, and add a runtime dependency to the Godot client. The existing tests pin byte-identical
  output across paths (Welcome vs Reveal statics, fog-off vs fog-on), which a foreign format breaks.
- **Reflection-based serialization** is ruled out by the hot path: 96 ship records per client per tick
  at 20 Hz must stay a memcpy of pre-serialized slices.

The generated code is the same straight-line little-endian span code the hand writers contained
(`BinaryPrimitives` at a running offset; no reflection, boxing, delegates or LINQ), so there is no
runtime cost, and every fixed record gets a `const int Size` the compiler checks. `tests/WireTest`
proves the generated bytes equal the legacy writers' bytes for every frame on the stock content
bundle and pins synthetic goldens so a later drift is caught even after the legacy writers are gone.

## Consequences
- One layout, one file: adding a field is a declaration; both ends, the tests and the bots compile it.
  `Wire.ProtocolVersion` is still bumped by hand — the goldens fail loudly when a layout moves.
- The reader never throws on hostile input (`TryParse` fails a truncated frame or a count that exceeds
  the bytes present before allocating), which the server's receive path did only by ad-hoc length
  guards before.
- Optional trailing fields (`[WireOptional]`) give the Hello and Spawn frames their "older sender may
  omit the tail" semantics declaratively; the same mechanism is how a future field can be added to a
  frame without a version bump when both ends tolerate its absence.
- A generator is one more build component: it targets netstandard2.0 and pins Microsoft.CodeAnalysis
  4.8, which loads unchanged on the Roslyn in the .NET 10 SDK and Godot's editor build. Generated
  partials are written under `shared/obj/.../generated/` for inspection.
- The switch-over is staged: this decision lands the generator, the definitions, the fill layer and the
  equivalence tests with the legacy writers untouched; the server and client switch in the following
  changes, each verifiable against the same goldens.
